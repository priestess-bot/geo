## 3. 当前阻塞项

### 3.1 真实外部采集仍未完成

- P0a 真实 provider key 尚未填充，核心缺口仍包括：
  - `OPENAI_API_KEY`
  - `PERPLEXITY_API_KEY`
- P0a preflight / small batch / full batch 尚未完成真实运行。
- 因此当前不能宣称正式客户报告已 ready。

### 3.2 Google P0b 仍未完成真实闭环

- Google selector/session/manual backfill/browser smoke/health spike/full spike/main scoring 仍未完成。
- Manual backfill 目前已有覆盖结构，但答案、引用、素材等内容完整性仍未达成正式放行口径。

### 3.3 运行态验证仍依赖本机 Docker 重启

- 前端 bundle 变更后，需要重建或重启 Web 容器才会在浏览器看到最新页面。
- Next.js dev server 首次访问仍会有编译耗时；这与 `/ops` API fanout 过重是两个不同问题。
- 当前已优化 `/ops` 的服务端接口请求量，但还未做生产构建模式性能对比。

### 3.4 客户交付状态仍是试点而非正式上线

- 当前工程具备试点演示基础，但正式客户报告交付硬门禁仍未清零。
- 主要原因是外部 provider、真实批次、Google 采集和正式报告全量交付链路未跑通。

## 4. 接下来任务规划

### 4.1 立即任务：运行态验收与页面体验收口

目标：确保当前浏览器访问到的就是最新前端，并确认 `/ops` 性能修复实际生效。

任务：

- 重建/重启 Docker Web 容器。
- 访问 `/`，确认客户首页无内部排障信息。
- 访问 `/ops?tab=project&project_id=...`，确认：
  - 中文化仍保留。
  - 项目配置页宽度正常。
  - 大面板可折叠。
  - 首屏加载明显少于之前。
- 对 `/ops` 各 tab 做一次人工走查，记录仍未翻译或过密的区域。

验收：

- 客户首页和内部控制台分工清晰。
- `/ops` 项目配置页不再触发所有重接口。
- 无明显布局挤压、文本重叠或 404。

### 4.2 P0a：真实 provider 凭证与首批采集

目标：把当前 fixture / dry-run 状态推进到真实 AU P0a 数据。

任务：

- 跑 P0a environment checklist。
- 跑 preflight batch。

验收：

- P0a credential gate 通过。
- 至少有真实 AU evidence runs。
- CollectionRunSummary 能展示 attempted/success/failure/cost/duration。

### 4.3 P0b：Google 采集与有限覆盖结论

目标：形成可解释的 Google coverage appendix，而不是阻塞主评分。

### 4.4 P0c：客户可交付报告
