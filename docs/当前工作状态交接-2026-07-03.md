## 2. 本轮完成的核心进展

本轮重点是把“独立 Admin Web + 独立 Customer Web + Runtime API”真正打通，解决此前前后端不协调、页面仍为占位或只能说明流程的问题。

### 2.1 Admin Web 新建项目闭环

新建项目页已从静态表单/占位按钮改为真实 Server Action。

关键文件：

- `apps/admin-web/app/runtime.ts`
- `apps/admin-web/app/projects/new/CreateProjectForm.tsx`
- `apps/admin-web/app/projects/new/actions.ts`
- `apps/admin-web/app/projects/new/page.tsx`

当前能力：

- `/projects/new` 提供完整项目创建向导。
- 表单提交调用 `POST /v1/projects/runtime/au/dtc-ecommerce`。
- 创建时会校验竞品数量为 3 到 5 个。
- `schedule` 和 `external_connectors` 使用 JSON 对象解析，不再当普通字符串处理。
- 创建成功后返回项目详情入口、客户邀请入口和一次性 raw invite token。
- 邀请链接通过 `customerInvitationUrl` 生成，指向 Customer Web，不再是 Admin 当前域名下的相对路径。

### 2.2 Admin Web 项目详情接入客户访问管理

项目详情页已接入真实客户入口管理能力。

关键文件：

- `apps/admin-web/app/projects/[project_id]/page.tsx`
- `apps/admin-web/app/projects/[project_id]/ProjectActions.tsx`
- `apps/admin-web/app/projects/[project_id]/actions.ts`

当前能力：

- 读取项目、启动配置、成员、邀请、portal token 元数据。
- 读取评分快照、报告、报告任务、行动计划、信源图谱。
- 支持创建客户 viewer 邀请。
- 支持生成 portal token。
- 支持撤销 portal token。
- raw token 和 raw invite token 只在创建成功时显示一次。
- 页面不再使用 inert `type="button"` 假操作。

### 2.3 Customer Web 接入真实 runtime 数据

Customer Web 已从占位看板改为基于 invitation 或 portal token 的单项目客户门户。

关键文件：

- `apps/customer-web/app/runtime.ts`
- `apps/customer-web/app/page.tsx`
- `apps/customer-web/app/portal/[module]/page.tsx`

当前能力：

- 支持 `portal_token` 直接进入。
- 支持 `invitation_id + invite_token` 首次进入并换取 portal token。
- 从 portal bundle 中读取 `member_user_id`，后续 runtime 数据读取使用该身份作为 `X-GENO-Actor-Id`。
- 首页展示真实项目、客户、启动配置、竞品数量、审计事件、报告数量和最新可见度分数。
- 模块页读取真实 runtime API：
  - `/v1/visibility-scores/runtime`
  - `/v1/evidence-runs/runtime`
  - `/v1/collection-runs/runtime`
  - `/v1/citation-graphs/runtime`
  - `/v1/reports/runtime`
  - `/v1/report-export-jobs/runtime`
  - `/v1/action-plans/runtime`
  - `/v1/traceability/runtime`

### 2.4 Customer Web 报告下载代理

报告 artifact 不再直接暴露需要后端 actor header 的 API 链接。

关键文件：

- `apps/customer-web/app/api/report-artifact/route.ts`
- `apps/customer-web/app/portal/[module]/page.tsx`

当前流程：

1. Customer Web 模块页生成 `/api/report-artifact` 链接。
2. Route handler 校验 `portal_token`。
3. 后端返回 portal bundle 后，route handler 取 `member_user_id`。
4. route handler 使用 `X-GENO-Actor-Id` 代理访问 `/v1/reports/runtime/{report_export_id}/artifact`。
5. 支持 `markdown`、`csv`、`pdf` 三种 artifact 类型。

### 2.5 API 补齐 portal token 元数据列表

Admin 项目详情需要显示已有 token 元数据，因此 API 和 repository 已补齐列表能力。

关键文件：

- `apps/api/geno_api/runtime_access_routes.py`
- `packages/geno_core/geno_core/runtime_project_access_repository.py`
- `tests/test_api_contracts.py`

新增端点：

```text
GET /v1/customer-portal/tokens/runtime
```

行为：

- 需要项目管理角色权限。
- 返回指定项目的 customer portal token 元数据。
- 不返回 `token_hash`。
- 不返回 raw token。

### 2.6 Compose 补齐 Customer Web base URL

Admin 生成客户邀请链接需要知道 Customer Web 的浏览器可访问地址。

关键文件：
