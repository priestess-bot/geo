# 图 3 · Evidence-first 数据流水线与复测闭环（新版设计稿）

用途：说明 GENO SaaS 澳大利亚首发 MVP 的运行时数据流。读者应一眼看出：系统先采集和保存原始证据，再解析、评分、建信源图谱、做竞品对标、出证据报告，最后按同一口径复测。

## 1. 图的核心论点

这张图只表达五件事：

1. **先证据，后结论**：没有 `Raw Evidence Store`，不允许产生评分、图谱、竞品结论或报告。
2. **触发与提及分母分离**：Google AIO 没触发和触发后没提品牌是两种状态。
3. **审计、溯源、解释原生处理**：关键动作写 `AuditEvent`，关键结论写 `EvidenceLink`，分数写 `ScoreContribution`。
4. **非确定性原生处理**：每个 prompt、平台、城市用 k=3 重复采样，报告展示均值和离散度。
5. **复测同口径**：T+7/14/30 必须复用同一 `prompt_version` 和 `sample_size`。

## 2. 画布与布局

画布：双栏横向，左到右主数据流。

主轴分为 6 段：

```text
配置 -> 采集 -> 原始证据 -> 解析/图谱 -> 评分解释/竞品/行动 -> 报告快照/复测
```

`Raw Evidence Store` 放在画布中央，做成最大、最重的圆柱节点。

画面底部放一条虚线复测回路，从 `Retest Scheduler` 回到 `AI Answer Runner`。复测必须从冻结的 `ReportExport` 快照出发，而不是从可变的当前页面状态出发。

画面上方放一条浅色方法学带，贯穿采集到报告：

```text
Methodology: access_method · answer_present · surface_triggered · k=3 · formula_version · audit_event_id
```

## 3. 视觉编码

| 语义 | 形状/样式 |
| --- | --- |
| 配置/处理阶段 | 圆角矩形 |
| 原始证据库 | 加粗朱红圆柱，视觉最大 |
| 数据制品 | 折角文档 |
| 方法学字段 | 淡黄小标签 |
| 审计/溯源轨 | 浅黄横带或圆角节点 |
| 报告快照 | 加粗折角文档，标注不可覆盖 |
| 主数据流 | 实线实心箭头 |
| 分叉/汇聚 | 实线箭头 |
| 复测回路 | 虚线开放箭头 |
| 不进入 P0 的能力 | 灰色虚线节点 |

## 4. 节点设计

### 4.1 配置段

左侧放两个上下堆叠节点：

```text
AU MarketProfile
platform weights · cities · source types
```

```text
IndustryProfile
1 industry · report template · source weights
```

二者汇入：

```text
Prompt Pack
100 prompts · en-AU · intent · city · prompt_version
```

Prompt Pack 节点旁放淡黄标签：

```text
P0: 100 prompts
upper bound: 200
```

### 4.2 采集段

Prompt Pack 指向：

```text
AI Answer Runner
CollectorBackend adapters
Google AIO · Google AI Mode · ChatGPT · Perplexity
```

在 Runner 下方放 4 个小 surface 节点：

```text
google_aio
google_ai_mode
chatgpt_search
perplexity
```

其中 `google_aio` 和 `google_ai_mode` 用朱红描边，标注：

```text
P0 spike · high product weight
```

Runner 旁放方法学标签：

```text
access_method
browser / official_api / third_party_api / manual
```

### 4.3 原始证据段

中央最大节点：

```text
Raw Evidence Store
Single Source of Evidence
```

圆柱内部画 5 个折角文档：

```text
AnswerRun
RawAnswer
AnswerCitation
EvidenceAsset
CollectorLog
```

节点旁放 2 个淡黄标签：

```text
answer_present
surface_triggered
```

```text
sample_index / sample_size
k = 3
```

Runner 到 Evidence 的箭头标注：

```text
write raw evidence before analysis
```

Evidence 下方放一条浅黄审计/溯源轨：

```text
Audit / Provenance Trail
AuditEvent · EvidenceLink · ScoreSnapshotRun · ReportEvidence
```

从 `AI Answer Runner`、`Raw Evidence Store`、`Answer Parser`、`Citation Graph`、`AUVisibilityScore`、`Competitor Benchmark`、`Evidence Report` 各画细实线写入该轨。

### 4.4 解析与图谱段

Raw Evidence Store 分叉到两个并行分支：

上分支：

```text
Answer Parser
brand · recommendation · rank · sentiment · local relevance
```

下分支：

```text
Citation Graph
source domain · source type · source gap · competitor source
```

Parser 输出：

```text
AnswerAnalysis
analysis_version · confidence · uncertainty_flags
```

Citation Graph 输出：

```text
SourceGraph
answer_run_ids · source_gap_type
```

### 4.5 评分、竞品和行动段

AnswerAnalysis 指向：

```text
AUVisibilityScore
au_visibility_v1
8 metrics · formula_version
```

AUVisibilityScore 节点旁放淡黄标签：

```text
Trigger Rate = surface_triggered / attempts
Mention Rate = brand_mentioned / surface_triggered
Recommendation Rate = brand_recommended / surface_triggered
```

AUVisibilityScore 指向一个折角文档节点：

```text
ScoreContribution
component_score · weight · denominator
positive/negative evidence · limitations
```

该节点旁放淡黄标签：

```text
must explain every total/platform/city/intent score
```

AUVisibilityScore 与 Citation Graph 共同指向：

```text
Competitor Benchmark
3-5 competitors · overlap · city advantage · intent advantage
```

Citation Graph 与 Competitor Benchmark 共同指向：

```text
Action Plan
source gap -> task
owner · status · next_check_date
```

Action Plan 用稍淡颜色，标注：

```text
P1 full version
P0 report only gives light recommendations
```

### 4.6 报告与复测段

五路汇入报告：

```text
ScoreContribution -> Evidence Report
Citation Graph -> Evidence Report
Competitor Benchmark -> Evidence Report
Action Plan -> Evidence Report
Audit / Provenance Trail -> Evidence Report
```

报告节点：

```text
Evidence Report
PDF / CSV
methodology · evidence appendix · audit summary · explanation bundle
```

报告旁放淡黄标签：

```text
must show:
sample size
access method
trigger/mention denominators
score formula version
API vs UI spot-check
audit summary
score explanation bundle
```

报告指向不可覆盖快照：

```text
ReportExport
immutable snapshot
answer_run_ids · score_snapshot_ids · prompt_version
formula_version · platform_weights · sample window
```

ReportExport 再指向：

```text
Retest Scheduler
T+7 / T+14 / T+30
```

Retest Scheduler 用虚线回路回到 AI Answer Runner，回路线标注：

```text
same prompt_version
same sample_size k=3
same market/city/device where possible
```

报告快照旁标注：

```text
重新导出 = 新 ReportExport 版本
不得覆盖旧报告
```

## 5. P2 能力放置

在 Action Plan 后方或下方放两个灰色虚线节点，不接入 P0 主链：

```text
P2 Content Engine
FAQ · comparison · schema · landing outline
```

```text
P2 Integrations
GSC · GA4 · Shopify · WordPress · HubSpot
```

从 Action Plan 到 P2 Content Engine 画一条细虚线，标注：

```text
enabled after evidence/source gap exists
```

不要让 P2 节点视觉上比 Evidence Report 更重。

## 6. 必须出现的标注

标注 1，证据库旁：

```text
No raw evidence, no score.
```

标注 2，Google surface 节点旁：

```text
AIO not triggered ≠ brand absent
```

标注 3，评分节点旁：

```text
双分母：Trigger Rate 与 Mention Rate 分开报
```

标注 4，复测回路旁：

```text
复测不是新口径采集；必须同 prompt_version、同 k。
```

标注 5，审计/溯源轨旁：

```text
每个报告数字必须能走：
ReportExport -> VisibilityScoreSnapshot -> ScoreContribution -> AnswerAnalysis -> AnswerRun
```

## 8. 图例

图右下角：

```text
朱红加粗圆柱 = 单一原始证据源
淡黄标签 = 方法学/采样口径
浅黄轨道 = 审计/溯源链路

```

## 9. 质量检查

出图前检查：

- `Raw Evidence Store` 是否是视觉中心。
- 是否明确 `answer_present` 与 `surface_triggered`。
- 是否明确 k=3 和 `sample_index / sample_size`。
- 是否明确 Trigger Rate 与 Mention Rate 分母不同。
- 是否把 Google AIO / AI Mode 画成 P0 high-weight spike。
- 是否把 P2 Content Engine / Integrations 放在灰色虚线后续区域。
- 是否能沿任意报告结论追溯回 `answer_run_ids`。
- 是否出现 `AuditEvent`、`EvidenceLink`、`ScoreContribution`、`ReportExport`。
- 是否明确报告从 `ReportExport` 快照进入复测，而不是从可变当前状态进入复测。
