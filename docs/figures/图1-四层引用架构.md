# 图 1 · Evidence-first 四层系统架构图（新版设计稿）

用途：用于说明 GENO SaaS 澳大利亚首发 MVP 的静态系统结构。读者应一眼看出：这是一个以 `Raw Evidence Store` 为事实中心、以接口契约实现可替换的证据型平台，而不是内容生成优先的营销工具。

## 1. 图的核心论点

这张图只表达三件事：

1. **分层**：控制台、应用编排、能力模块、开源基础设施四层单向依赖。
2. **证据中心**：`Raw Evidence Store` 是 P0 核心，所有评分、信源图谱、竞品对标和报告都从证据库读取。
3. **可插拔**：采集、解析、评分、图存储、LLM、地理定位、报告导出都通过接口契约替换。

不要在图 1 表达运行时数据流细节；数据流留给图 3。

## 2. 画布与布局

画布：纵向四层泳道，建议双栏宽度 180mm 或单栏宽度 88mm 的纵向版本。

从上到下四层：

```text
L1 控制台层
L2 应用编排层
L3 能力模块层
L4 开源基础设施层
```

左侧画一条细灰色竖轴，标注：

```text
依赖方向：自上而下，单向
```

右侧画一条朱红色竖向括号，跨越 L3 到 L4，标注：

```text
可替换接口层：新增适配器，不改业务主线
```

## 4. 节点设计

### L1 控制台层

居中放 1 个节点：

```text
Next.js 控制台
项目 · Prompt · 证据 · 信源 · 竞品 · 报告
```

### L2 应用编排层

横向放 3 个圆角矩形：

```text
Project Orchestrator
项目/市场/行业/竞品配置

Run Orchestrator
采集任务 · k=3 · 复测窗口

Report Orchestrator
评分快照 · 证据附录 · 导出
```

右侧单独放 1 个圆角矩形，稍微错开：

```text
Collector Worker
与主服务隔离
```

在 `Collector Worker` 旁加 callout：

```text
采集脆弱，必须隔离
```

### L3 能力模块层

按“证据在中心”的布局，不再按普通 2x4 均匀排列。

中心放大节点：

```text
Raw Evidence Store
AnswerRun · RawAnswer · Citation · Screenshot · HTML · Hash
```

该节点用加粗朱红圆柱，作为全图视觉中心。

左侧放采集与输入模块：

```text
MarketProfile
IndustryProfile

Prompt Pack
100 prompts · en-AU · city · intent · version

AI Answer Runner
Google AIO / AI Mode · ChatGPT · Perplexity
```

右侧放分析与输出模块：

```text
Answer Parser
brand · competitor · rank · sentiment · local relevance

ScoringEngine
au_visibility_v1 · trigger/mention 双分母

CitationGraph
source gap · local source · competitor source

CompetitorBenchmark
3-5 competitors · overlap · advantage

ActionPlanner
source gap -> task

ReportExporter
PDF / CSV · evidence appendix
```

### L3 接口标签

在对应模块右上角贴朱红虚线标签：

```text
AI Answer Runner      «CollectorBackend»
Answer Parser         «ParserEngine»
ScoringEngine         «ScoringFormula»
CitationGraph         «GraphStore»
ActionPlanner         «LLMGateway»
ReportExporter        «ReportExporter»
MarketProfile/Runner  «GeoProvider»
```

注意：`Raw Evidence Store` 不贴可替换接口标签。它是事实中心，不是可随意替换的业务语义层；它下面的存储实现可以替换。

## 5. 连线规则

```text

```



## 6. 必须出现的标注

标注 1，放在证据库旁：

```text
Single Source of Evidence
所有分数、引用、结论必须可回溯到 AnswerRun
```

标注 2，放在采集 Worker 旁：

```text
API ≠ consumer UI
AIO 选择性触发
采集结果必须记录 access_method 与 surface_triggered
```

标注 3，放在 ScoringEngine 旁：

```text
au_visibility_v1
Trigger Rate 与 Mention Rate 分母不同
```

标注 4，放在右侧接口括号旁：

```text
接口前置：换实现只新增 adapter
```

## 8. 质量检查

出图前检查：

- `Raw Evidence Store` 是否是视觉中心。
- 是否能看出采集 Worker 与主服务隔离。
- 是否出现 `answer_present / surface_triggered / access_method` 的采集口径。
- 是否明确 Google AIO / AI Mode、ChatGPT、Perplexity 是 P0 目标 surface。
- 是否没有把 Content Engine 画成 P0 主线。
- 是否能看出所有下游结论都依赖证据库。
