# 图 2 · P0 可插拔接口与实现矩阵（新版设计稿）

用途：说明 GENO SaaS 澳大利亚首发 MVP 的可替换实现边界。读者应一眼看出：哪些接口必须先定义，哪些实现属于 P0，哪些只是 P1/P2 备选，以及 Google AIO / AI Mode 虽然采集难，但仍是 P0 高权重目标。

## 1. 图的核心论点

这张图只表达三件事：

1. **8 个接口是工程边界**：业务代码依赖接口，不依赖具体实现。
2. **P0 实现与备选实现分层**：默认实现、P0 spike、P1/P2 后续实现要视觉区分。
3. **采集不是一个接口就完事**：`CollectorBackend` 下要明确平台 surface、access method、保真度抽检。

## 2. 画布与布局

画布：横向矩阵，建议双栏宽度 180mm。

列结构：

```text
接口契约 | P0 默认实现 | P0 高风险 / spike 实现 | P1/P2 备选实现 | 必须记录的口径
```

行结构：8 行，每行对应 1 个接口。

行顺序：

```text
1. CollectorBackend
2. GeoProvider
3. LLMGateway
4. ParserEngine
5. ScoringFormula
6. GraphStore
7. VectorStore
8. ReportExporter
```

把 `CollectorBackend` 放第一行，并让这一行高度约为普通行的 1.8 倍，因为采集是 P0 最大风险。

## 3. 视觉编码

| 语义 | 形状/样式 |
| --- | --- |
| 接口契约 | 朱红虚线折角标签 `«Interface»` |
| P0 默认实现 | 深灰实线圆角 chip，浅灰填充 |
| P0 spike / 高风险实现 | 朱红描边圆角 chip，浅橙填充 |
| P1/P2 备选实现 | 灰色虚线圆角 chip，白底 |
| 必须记录口径 | 小号等宽字段列表，淡黄底 |
| 可 A/B 或并存 | 朱红 `⇄` |
| 实现关系 | 空心三角箭头：实现 -> 接口 |

图例必须写清楚：

```text
P0 默认 = 可先打通垂直链路
P0 spike = 必须验证，但实现风险高
P1/P2 = 后续增强，不阻塞 P0
```

## 4. 矩阵逐行内容

### 4.1 `«CollectorBackend»`

接口契约：

```text
«CollectorBackend»
collect(prompt, market, city, language, device) -> RawCollectResult
```

P0 默认实现：

```text
PerplexitySonarCollector
access_method = official_api

OpenAIWebSearchCollector
access_method = official_api
```

P0 高风险 / spike 实现：

```text
PlaywrightGoogleAIOCollector
surface = google_aio
access_method = browser

PlaywrightGoogleAIModeCollector
surface = google_ai_mode
access_method = browser

ThirdPartySerpCollector
surface = google_aio
access_method = third_party_api
```

P1/P2 备选实现：

```text
PlaywrightChatGPTCollector
PlaywrightPerplexityCollector
BingCopilotCollector
GeminiCollector
ClaudeCollector
ManualBackfillCollector
SearXngBaselineCollector
```

必须记录的口径：

```text
platform
surface
access_method
answer_present
surface_triggered
collector_backend_id
collector_version
sample_index / sample_size
```

行内 callout：

```text
Google AIO / AI Mode = P0 高权重目标，不是可选项；只是实现以 spike 管理。
```

## 5. 标注与图例

右侧放纵向注释框：

```text
替换规则：
1. 业务模块只依赖接口契约
2. 新实现只新增 adapter
3. 所有实现必须写入同一数据契约
4. 报告必须展示 access_method 与 sample_size
```

底部脚注：

```text
平台评分权重 ≠ 构建顺序。
Perplexity/ChatGPT 先打通链路；Google AIO/AI Mode 是 P0 高权重 spike，不得从产品范围中删除。
```

## 6. 质量检查

出图前检查：

- `CollectorBackend` 是否是第一行且视觉最重。
- Google AIO / AI Mode 是否被标为 P0 spike，而不是普通备选。
- 是否出现 `answer_present`、`surface_triggered`、`access_method`、`sample_index/sample_size`。
- 是否区分 P0 默认、P0 spike、P1/P2 备选。
- 是否明确替换实现只新增 adapter。
- 是否没有把 Copilot/Gemini/Claude 误画成 P0 默认。
