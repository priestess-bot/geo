本文遵守四条原则：

1. 先打通一条真实生产闭环，再横向扩展模块。
2. 每个任务必须落到数据库、API、worker、前端、权限、审计、测试、文档和回滚中的具体变更。
3. 所有环境、所有页面、所有报告都不得用 fixture/demo 数据冒充生产能力。
4. 身份认证、对象存储、队列、监控、向量检索、图存储、LLM 网关、浏览器自动化、文档解析、PDF 渲染、邮件发送、复杂 UI 控件等通用基础能力优先复用成熟组件，只自研 GEO 业务契约和适配层。

## 1. 执行层级

采用以下层级管理实现：

```text
Master Production Plan
  -> Milestone
    -> Epic
      -> Feature
        -> Task
          -> Migration / API / UI / Worker / Permission / Audit / Test / Doc / Rollback
```

每个 Task 必须写清：

- 目标。
- 依赖。
- 涉及模块。
- 数据库变更。
- API 变更。
- 前端变更。
- worker 变更。
- 权限规则。
- 审计事件。
- 测试用例。
- 验收方式。
- 回滚方式。

未满足上述字段的事项只算想法，不允许进入开发排期。

## 2. 纵向闭环优先级

第一条必须打通的生产闭环是：

```text
租户
  -> 用户登录
  -> 创建项目
  -> 配置品牌/竞品/Prompt
  -> 配置一个真实 connector
  -> 真实采集
  -> 保存 RawAnswer / AnswerCitation / EvidenceAsset
  -> 自动解析
  -> 计算 VisibilityScoreSnapshot / ScoreContribution
  -> 生成 ReportExport
  -> 客户安全查看报告
  -> 审计追溯
```

这条链路未完成前，不进入知识库、内容生成、分发自动化的大规模开发。否则系统会出现很多页面都有、但没有任何真实客户链路稳定可用的问题。

## 3. 里程碑

| 里程碑 | 名称 | 目标 | 退出标准 |
| --- | --- | --- | --- |
| M0 | 架构冻结与工程基线稳定 | 固定边界，修复当前阻断 | 全量测试绿；端口和文案口径稳定；demo fallback 清除 |
| M1 | 多租户与权限可用 | 真实用户、租户、角色、项目授权可用 | 登录、session、RBAC、RLS、越权测试通过 |
| M2 | 单平台真实采集闭环 | 先用一个真实 connector 跑通证据链 | 真实采集、证据、成本、失败重试、审计通过 |
| M3 | 多平台采集与 Google 风险路径 | 扩展 OpenAI/Perplexity/Google 路径 | 多平台调度、限流、成本、Google 风险预案可用 |
| M4 | 评分、报告与客户门户闭环 | 把真实证据交付为客户报告 | 评分可解释；报告可发布/撤回；客户安全查看 |
| M5 | 行动计划与复测闭环 | 从报告进入持续优化 | 行动建议、任务、复测、趋势、告警可用 |
| M6 | 知识库、内容与分发闭环 | 补齐完整 GEO 服务链 | 知识事实、内容审核、分发回填、复测关联可用 |
| M7 | 生产运维与安全验收 | 达到长期生产运行要求 | 监控、备份、恢复、安全、压测、部署演练通过 |

运维、安全、secret、日志脱敏、迁移验证和 CI 门禁不等到 M7 才做，必须从 M0 开始贯穿所有里程碑。

## 3.1 里程碑 Go / No-Go 门禁

每个里程碑结束时必须明确 Go / No-Go。Go 表示允许进入下一里程碑；No-Go 表示必须停止新增业务功能，先修复阻断。

### M0 Go / No-Go

必须通过的命令：

```bash
python3 -m ruff check apps/api/geno_api packages/geno_core/geno_core workers scripts tests
PYTHONDONTWRITEBYTECODE=1 python3 -m compileall apps/api/geno_api packages/geno_core/geno_core workers scripts tests
PYTHONDONTWRITEBYTECODE=1 PYTHONPATH=packages/geno_core:apps/api python3 -m unittest discover -s tests
npm --prefix apps/admin-web run typecheck
npm --prefix apps/customer-web run typecheck
npm --prefix apps/dashboard-web run typecheck
npm --prefix apps/admin-web run build
npm --prefix apps/customer-web run build
npm --prefix apps/dashboard-web run build
make docker-config
make docker-config-observability
make db-smoke
make runtime-e2e
git diff --check
```

必须完成的修复：

- 全量测试绿。
- `db-smoke` 默认端口不再被本机 5432 阻断。
- observability 默认端口不与 Admin Web 冲突。
- Dashboard 和用户可见文案统一 GEO 口径。
- 真实项目创建路径不再使用 demo fallback。
- KoalaHome 脏竞品数据已清理，且前后端禁止再次写入。
- FastAPI、Repository、Connector、证据链 ADR 已落地。
- Auth Provider、任务队列、对象存储、监控告警、向量/搜索、图存储、文档解析、报告渲染/邮件、前端组件 ADR 已接受并与实施计划一致。

允许带入 M1 的风险：

- 真实 OpenAI/Perplexity/Google 采集未完成。
- 知识库、内容、分发未完成。
- M5-M7 细任务仍是边界级规划。

禁止进入 M1 的情况：

- 全量测试仍失败。
- 生产路径仍能写入 `ExampleBrand`、`AU GEO Pilot` 等 demo fallback。
- 客户入口仍把长期 token 放在 URL query 且没有替代设计 ADR。
- 权限模型和 Auth Provider 选型没有冻结。
- connector 接口没有冻结。

### M1 Go / No-Go

必须通过：

- 登录、退出、邀请兑换、session 过期测试。
- RBAC allow/deny 合同测试。
- RLS smoke 覆盖新增租户/成员/项目访问表。
- Customer portal 不再依赖 query token。

禁止进入 M2 的情况：

- API 仍允许绕过 actor/project scope。
- Client Viewer 可越权访问其他项目或未发布报告。
- provider key 可被无权限角色读取或写入。

### M2 Go / No-Go

必须通过：

- 一个真实 connector health check。
- 一个真实项目 10 Prompt 采集。
- RawAnswer、AnswerCitation、EvidenceAsset、CollectionCost、AuditEvent 写入完整。
- 失败重试和错误分类测试。

禁止进入 M3 的情况：

- 真实采集结果不能追溯到 evidence asset。
- 采集失败无法解释。
- provider key 明文出现在 API response、日志或报告中。

### M3 Go / No-Go

必须通过：

- 第二个平台真实采集闭环。
- Google manual/browser/SERP 至少一个路径完成小批量可行性验证。
- 成本模型和预算阈值可用。

禁止进入 M4 的情况：

- Google 数据来源和局限没有方法披露口径。
- 多平台数据混入同一分母但无法区分 access_method 和 sample window。

### M4 Go / No-Go

必须通过：

- 最小客户报告模板冻结。
- ReportExport 不可覆盖。
- 客户可安全查看已发布报告。
- 报告数字可追溯到 answer_run 和 evidence_asset。

禁止进入 M5 的情况：

- 客户可查看未发布报告。
- 报告撤回后客户仍可下载。
- ScoreContribution 缺失导致总分无法解释。

#### Task M0.1.5 Auth Provider ADR

- Owner：Backend。
- Priority：P0。
- Size：S。
- Can Parallelize：yes，可与 M0.1.1-M0.1.4 并行。
- 目标：冻结身份认证方案，避免 M1 实现时临时选择导致 session、邀请、RBAC、Customer portal 和部署方式返工。
- 依赖：[GEO技术选型与复用策略-2026-07-05.md](GEO技术选型与复用策略-2026-07-05.md)。
- 涉及模块：docs/decisions、API auth、Admin Web、Customer Web。
- 数据库变更：定义是否需要 `users`、`sessions`、`identity_provider_accounts`、`tenant_members`、`project_members`。
- API 变更：定义登录、登出、当前用户、邀请兑换、session refresh、session revoke 的接口边界。
- 前端变更：定义 Admin/Customer 登录方式和 session cookie 读取方式。
- worker 变更：定义系统任务 actor 和用户触发任务 actor 的区别。
- 权限规则：未登录 401，无权限 403；Customer Viewer 必须绑定 tenant/project scope。
- 审计事件：定义 `user_logged_in`、`user_logged_out`、`invitation_redeemed`、`session_revoked`、`access_denied`。
- 测试用例：ADR 必须列出 magic link/password/OIDC/session cookie/SSO 取舍对应测试。
- 验收方式：ADR 明确选择 Keycloak/OIDC、托管 Auth provider、Auth.js/Supabase Auth 或短期内置 session 中的一个，并写清替换路径。
- 回滚方式：ADR 版本化；未落代码前无运行时影响。

## 15. 风险与并行策略

### Google 采集风险

Google AI Mode / AI Overviews 是最高不确定性模块，必须并行验证，不等到所有权限和 OpenAI/Perplexity 完成后再开始。

并行策略：

- M0/M1：冻结 Google 方法披露和风险 ADR。
- M2：人工补录模板和证据模型先对齐。
- M3：浏览器和 SERP provider 小批量验证。
- M4：报告中按 access_method 披露 Google 数据来源和局限。

生产策略：

- 浏览器路径稳定时，可进入正式评分，但必须披露采样窗口和触发率。
- 第三方 SERP 路径可作为对照或正式数据源，取决于供应商返回的可解释程度。
- 人工补录可进入报告附录或正式报告，但必须有双人复核、证据附件和方法说明。
- 任何 Google 路径不稳定时，不能把缺失误算成品牌缺失。

### 范围失控风险

控制方式：

- M2 前只做一个真实 connector。
- M4 前不展开知识库和内容工作台。
- 每个新平台必须复用 connector interface，不允许写死页面和报告。
- 每个大模块必须先有一个端到端验收场景，再补高级功能。

### 成本失控风险

控制方式：

- 每个项目配置月预算。
- 每个采集计划预估成本。
- 失败重试有预算比例。
- 超阈值先告警，再 hard stop。
- 客户报告披露样本数量和时间窗，不追求无边界全量采集。

## 17. 与 Master Plan 的关系

Master Plan 继续作为最终生产目标和投产边界。本文作为执行计划，会随实现进展继续拆分任务。

判断标准：

- Master Plan 回答“最终必须是什么”。
- Implementation Plan 回答“下一步具体改什么、测什么、怎么验收、怎么回滚”。

如果两份文档冲突，以“真实用户可投产、真实数据可追溯、真实权限可验证”为最高原则。
