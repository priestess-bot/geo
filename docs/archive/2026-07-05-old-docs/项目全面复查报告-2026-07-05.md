## 5. 主要问题清单

### P0 - 真实客户可用阻塞

1. 真实外部采集未 ready  
   证据：启动配置仍为 `fixture`；OpenAI/Perplexity 为 `not_configured`，Google AI Mode 为 `fixture_only`。README/交接文档也明确真实 key、账号、session、selector、manual backfill 仍是 blocker。  
   影响：不能对客户声明真实 OpenAI/Perplexity/Google GEO 采集和评分已经可交付。  
   验收：补齐 `.env.au-p0a`、`.env.au-p0b-google` 后跑 strict gates，包括 `--require-complete`、`--require-fulfilled`、`--require-cleared` 和真实 batch/spike 验证。

2. 当前测试基线不是全绿  
   证据：`python3 -m unittest discover -s tests` 运行 1282 个测试，失败 2 个：`test_dashboard_app_is_static_json_backed_chinese_dashboard`、`test_customer_home_is_chinese_read_only_dashboard`。  
   原因：测试仍断言 `<html lang="zh-CN">`，代码已改为 `<html lang="zh-CN" suppressHydrationWarning>`。  
   影响：CI/交付门禁会失败或被迫跳过。  
   验收：更新契约测试，保留 `lang="zh-CN"` 与 hydration suppression 的预期。

3. 商用安全边界还不够硬  
   证据：Customer Web 将 `portal_token` 放在 URL query 中，并继续传给模块页和 `/api/report-artifact`。本地验证中有效 token 可访问首页和下载报告，无效 token 返回 401。  
   影响：query token 可能进入浏览器历史、Referer、代理日志、截图或客服排障记录。  
   验收：改为短期一次性 code + httpOnly session cookie，或至少加 token TTL、Referer policy、日志脱敏测试和 token 轮换/撤销回归。

### P1 - 发布前应修复

4. `db-smoke` 默认端口不可避让  
   证据：`make db-smoke` 首次失败：`Bind for 0.0.0.0:5432 failed: port is already allocated`；显式 `GENO_POSTGRES_HOST_PORT=18180 make db-smoke` 后通过。  
   影响：本地 CI/开发者验证不稳定，和自动端口策略不一致。  
   建议：`db-smoke` 和 `runtime-e2e` 默认也使用自动端口或不发布 host port。

5. Observability profile 与 Admin Web 默认端口冲突  
   证据：`docker-config-observability` 中 Grafana published `3001`，Admin Web 默认也 published `3001`。  
   影响：手动 Compose + observability 会端口冲突；自动端口能绕开，但默认配置仍不稳。  
   建议：Grafana 默认端口改为 `3003` 或接入统一自动端口。

6. 项目数据存在脏竞品名  
   证据：KoalaHome 项目 competitor 中出现 `canonical_name="1"`。  
   影响：报告、评分、竞品配置展示会出现无意义竞品，说明表单/API 缺少合理校验或操作误输入没有防护。  
   建议：前后端都校验竞品名长度、字符和重复项；为已有脏数据提供修正入口。

7. Dashboard 仍是 GENO/旧状态口径  
   证据：Dashboard title 为 `GENO 工程进展 Dashboard`，data `generatedAt=2026-06-26 Asia/Shanghai`；Playwright 检测正文没有 `GEO`。  
   影响：和用户已确认的 GEO 项目门面口径不一致，也可能展示过期状态。  
   建议：把 Dashboard 文案、metadata、静态 JSON 生成时间和“真实 ready”状态统一更新。

8. 测试日志噪声较大  
   证据：全量 unittest 中大量输出 `runtime_http_access_log_persist_failed`，原因是测试环境没有 `DATABASE_URL`。  
   影响：失败定位困难，也容易掩盖真正日志异常。  
   建议：测试环境关闭 access log 持久化，或将预期配置缺失降为可控 debug 级别。

9. 新建项目 Server Action 仍有 fallback 默认值  
   证据：`apps/admin-web/app/projects/new/actions.ts` 对 `tenant_name`、`project_name`、`target_brand` 等使用 `Design Partner AU`、`AU GEO Pilot`、`ExampleBrand` fallback。  
   影响：空输入可能创建 demo 化数据，不适合真实客户项目。  
   建议：真实模式下必填字段不得 fallback，fixture/demo 模式才允许预置测试数据。

### P2 - 质量与维护

10. API 和 Repository 热点过大  
    证据：`apps/api/geno_api/main.py` 承载大量 runtime endpoint；`packages/geno_core/geno_core/repository.py` 承载大量 SQL、状态机和审计逻辑。git 热点也集中在这两个文件。  
    影响：后续改动容易出现跨域回归。  
    建议：按项目访问、报告、通知、entity alias、交付状态拆分模块和测试。

11. 新增 RLS 表未使用 `FORCE ROW LEVEL SECURITY`  
    证据：`0015_customer_portal_launch_access_logs.sql` 对 `customer_portal_tokens`、`project_launch_configs`、`runtime_http_access_logs` 只 `ENABLE ROW LEVEL SECURITY`；`0010` 主体表大多 `FORCE ROW LEVEL SECURITY`。  
    影响：当前 runtime role 非 bypass，DB smoke 通过；但策略强度不一致。  
    建议：评估并补齐 FORCE RLS，统一租户隔离口径。

12. 文档仍混用 GEO/GENO、旧 `/ops` 与新 Admin/Customer 边界  
    证据：README 和 PROJECT-PLAN 大量历史追加内容，交接文档已说明旧 `apps/web` 仅保留为迁移源。  
    影响：新人启动和验收时容易跑错入口或误判 readiness。  
    建议：新增一份“当前唯一入口与状态”短文档，README 保留摘要并链接。
